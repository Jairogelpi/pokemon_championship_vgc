# Glosario

| Término | Significado en este proyecto |
|---|---|
| SDD | Desarrollo guiado por especificación: comportamiento y aceptación antes del código |
| TDD | Ciclo test que falla por el comportamiento esperado, implementación mínima y refactor |
| ARD | Architecture Requirements Document: requisitos y restricciones de arquitectura |
| ADR | Architecture Decision Record: decisión concreta, alternativas, consecuencias y estado |
| Ruleset | Reglas identificadas por formato/temporada/versión; no «reglas Pokémon» genéricas |
| SP | Stat Points de Champions; conversión y límites requieren fuente |
| BattleState | Proyección actual reconstruible; fuente de verdad operativa |
| Event log | Historial durable de eventos confirmados que permite reconstruir BattleState |
| Belief | Distribución de hipótesis rivales compatibles con evidencia |
| Snapshot | Versión inmutable de datos/meta con procedencia y fecha |
| Pick-4 | Selección legal de cuatro de los seis miembros propios |
| Lead / back | Dos activos iniciales y reservas seleccionadas |
| Ply | Unidad de profundidad de búsqueda; definición pendiente Q-005 |
| Golden | Fixture con resultado esperado respaldado por referencia independiente |
| Provenance | Origen comprobable de una afirmación o cálculo |
| Confidence | Score interno de confianza; no probabilidad calibrada salvo validación específica |
| Seed | Semilla de RNG inyectada para reproducibilidad |
| Handoff | Entrega de tarea, cambios, evidencias, límites y próximo paso entre agentes |
| Skill | Procedimiento especializado que carga el agente; no un proceso autónomo |
